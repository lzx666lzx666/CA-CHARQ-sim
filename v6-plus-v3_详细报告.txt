二、信道模型
================================================================================

2.1 传播损耗
────────────────────
    TL(d) = d_km^1.5 × 10^(0.04 × d_km)
    d_km = 距离(km)

包含扩展损耗(柱面-球面混合，指数1.5)和吸收损耗。

2.2 SNR 控制
────────────────────
    noise_var = TX_POWER_W / (TL(600m) × SNR_linear)

通过调节 noise_var 使每跳 600m 处接收 SNR 达到目标值(snr_db)。
snr_db 是接收端平均 SNR，已扣除传播损耗。

2.3 Rician 衰落
────────────────────
    los  = sqrt(K/(K+1))      = sqrt(2/3) ≈ 0.816
    nlos = sqrt(1/(2(K+1)))   = sqrt(1/6) ≈ 0.408

    I = los + nlos × N(0,1)
    Q = nlos × N(0,1)
    SNR_chunk = asnr × (I² + Q²)

每个 chunk 独立生成 I/Q，模拟块级衰落。K=2 时视距分量占主导，
E[|h|²] = 1，即衰落功率归一化。

六、协议逻辑详述
================================================================================

6.1 S&W ARQ (停等 ARQ)
────────────────────
性质: 无协作，纯源端重传

流程:
  1. 源端 tx_loop 发送 RV0 (100 块系统数据)
  2. 目的端 handle 累加 soft_buffer[0:100]，计算 MI
  3. MI ≥ 11000 → ACK → 跳完成 → 转发下一跳
  4. MI < 11000 → NACK (仅一次, nack_sent 标记)
  5. 源端收到 NACK → 发送 RV0_retry → 目的端 Chase 累加 → 重新判断
  6. 超时 (gto=7.3s) 或重传达 MAX_HOP_RETRYS=5 → 丢包

特征: 大延迟 (0dB 时 ~83s)、低开销 (10.4x)；Chase 合并累积 MI。
Helper: 无。S&W 拓扑中不创建 helper 节点。

6.2 C-ARQ (协作 ARQ)
────────────────────
性质: 1 个预选 helper (距中点最近)，helper 发送完整 RV0

流程:
  1. 源端发送 RV0，helper 侦听并解码
  2. 目的端失败 → 发送 NACK (一次) → 源端发 RV0_retry
  3. 预选 helper (已解码) 听到 NACK → 发送完整 RV0 (每 NACK 响应一次)
  4. 目的端对两路 RV0 做纯 Chase 合并 (无 IR)
  5. helper 每 pid 最多响应 MAX_HOP_RETRYS=5 次

特征: helper 无 IR 增益 (仅重复发送)，开销最高 (13-15x)，
      延迟与 S&W 持平；代表"最简单的协作形式"。

6.3 C-HARQ (协作 HARQ, Ghosh 2013)
────────────────────
性质: 1 个预选 helper (距中点最近)，Proactive 双 FEC 机制

流程:
  1. 源端发送 RV0，helper 侦听并解码
  2. 目的端失败 → 发送 NACK (一次) → 源端发 RV0_retry
  3. 预选 helper (已解码) 听到 NACK → 立即发送 Pac-1 (50 校验块, @100-150)
  4. 等待 3.53s 后无条件发送 Pac-2 (40 校验块, @150-190)
  5. 目的端累加: 源 RV0 → Chase 合并 (0-100)
                Pac-1 → IR 合并 (100-150)
                Pac-2 → IR 合并 (150-190)

特征: IR 增益显著减少所需传输次数，中高 SNR 延迟优于 S&W；
      但强制双 FEC 造成冗余浪费 (Pac-2 未必需要, 40 块纯浪费)。

6.4 CA-CHARQ (置信度自适应协作 HARQ) — 核心协议
────────────────────
性质: 3 个 helper 竞争 + 置信度量化 + 自适应 RV + Grace Period

6.4.1 置信度量化 (confidence_quantize)
────────────────────
    ratio = acc_mi / TARGET_MI
    ratio < 0.45   → cpkt=0  (低置信, 需要大量冗余)
    0.45 ≤ r < 0.65 → cpkt=1  (中低置信)
    0.65 ≤ r < 0.85 → cpkt=2  (中高置信)
    r ≥ 0.85        → cpkt=3  (高置信, 仅需少量助推)

6.4.2 目的端 handle
────────────────────
  - 接收 DATA → 按类别累加:
    · fec_idx>0: C-HARQ FEC 包 → IR 合并到对应区域
    · rv_level>0 (CA-CHARQ): 校验包 → IR 合并到 start_idx:end_idx
    · 其他: 系统数据 → Chase 合并到 0:100
  - 计算 acc_mi = Σ log2(1+soft_buffer[i]) × 80
  - MI ≥ TARGET → SUCCESS → ACK → 转发下一跳
  - MI < TARGET:
    · CA-CHARQ: 仅对源端数据 (hop_tx==hop_source) 发送 NACK_cpkt
      nack_count 增加, 上限 NACK_MAX=3
    · 对照组: 仅对源端数据且一次 NACK (nack_sent 标记)

6.4.3 源端 tx_loop + Grace Period
────────────────────
  - 发送 RV0 后等待 ACK/NACK/超时 (gto=7.3s)
  - 收到 NACK(cpkt) 且 cpkt ≥ 3 → 进入 Grace Period:
    · Grace_t = rv_tx_time + T_MAX_WINDOW/4 + 3×prop + 0.3s
    · rv_tx_time = RV1(2.0s) / RV2(4.0s) / RV3(6.0s) 根据 cpkt
    · 创建 helper_ack_event 等待
    · yield Grace 超时 OR ACK 事件
    · ACK 先到 → 跳成功 (helper 响应成功，源端跳过重传)
    · Grace 超时 → 源端发送 RV0_retry
  - CA-CHARQ 源端始终发送 RV0 (Chase 增益最大化)
  - 与对照组统一: 收到 NACK 立即发送 RV0 (非 Grace 时)

6.4.4 helper 竞争机制 (contend)
────────────────────
  得分公式:
    score = W1 × min(c_pkt, 1.5)          ← helper 自身置信度
          + W2 × max(0, min(1, energy/INITIAL_ENERGY))  ← 剩余能量
          + W3 / (1 + prop_to_midpoint / 0.4s)         ← 距中点近者优先

  退避定时器:
    t = (1 - clip(score, 0, 1)) × T_MAX_WINDOW × 2      ← 基本退避 (0~3.0s)
      + max(T_PROTECTION_GAP / 4, 0.05)                  ← 保护间隔 (≥0.05s)
    若 score > 0.90 → t = 0                             ← 零退避优化

  竞争取消:
    - 其他 helper 收听到获胜者对该链路的数据包
    - 触发 helper_cancel_events[pid] → 退避定时器终止

  获胜 helper 发送:
    cpkt≥2 → RV1 (30 校验块, 2.0s)  ← 高置信少量校验
    cpkt=1 → RV2 (60 校验块, 4.0s)  ← 中置信中等校验
    cpkt=0 → RV3 (90 校验块, 6.0s)  ← 低置信大量校验

6.4.5 helper 解码
────────────────────
  - 侦听源端 RV0 传输，Chase 累加 soft_buffer[0:100]
  - MI ≥ TARGET → 标记 DECODED, 存储 c_pkt (连续置信值) 和 cpkt
  - CA-CHARQ helper 额外存储置信度用于竞争得分

6.4.6 Grace ACK 触发
────────────────────
  - 源端收到 ACK → 检查 helper_ack_events
  - 若有 pending Grace 等待事件 → 触发 → Grace 成功

八、理论分析

8.1 MI 计算公式
────────────────────
    MI_per_chunk = log2(1 + SNR_chunk) × 80 bits
    MI_total = Σ MI_per_chunk (对所有已收块)

    一传近似 (忽略衰落):
    MI_1tx ≈ 100 × log2(1 + SNR_linear) × 80

8.2 关键 SNR 阈值
────────────────────
    SNR(dB)  SNR_lin  MI_1tx (理论)  需几传?
    ─────────────────────────────────────
    0.0      1.00       ~8000        2 传 (Chase → ~16000)
    0.5      1.12       ~8800        2 传
    1.0      1.26       ~9600        1~2 传
    1.5      1.41      ~10400        1~2 传 (临界)
    2.0      1.59      ~10970        1~2 传 (非常临界)
    2.5      1.78      ~11600        1~2 传 (部分成功)
    3.0      2.00      ~12600        1 传 (大概率成功)
    3.5      2.24      ~13600        1 传
    4.0      2.51      ~14500        1 传 (必成功)

    收敛 SNR (理论):
    TARGET_MI = 11000
    log2(1+SNR_conv) = 11000 / (100×80) = 1.375
    SNR_conv = 2^1.375 - 1 = 1.59 (线性) ≈ 2.03 dB

    实际收敛 ~3.5-4.0 dB (因 Rician 衰落方差增大)

8.3 TARGET_MI=11000 的理论意义
────────────────────
    等效 FEC 码率 = 8000/11000 ≈ 0.727 ≈ 3/4 码率
    对应实用 LDPC/Turbo 码所需 MI, 在水声通信中物理合理。
    在此阈值下, 0-4dB 区间恰好覆盖"必重传 → 临界 → 必成功"全过渡区,
    为四种协议提供了充裕的差异化区间。

9.3 结果解读
────────────────────
延迟排序 (0.5-3.0dB):
  CA-CHARQ < C-HARQ < C-ARQ ≈ S&W

0dB 持平原因:
  Cpkt=2 (ratio≈0.73) → Grace 不激活 (仅 cpkt≥3)
  → 源端必须 2 次 RV0 (Chase 主导延迟 ≈14s/跳)
  → 这是低 SNR 下的物理限制: 信息积累需要多次合并

开销:
  CA-CHARQ 在 2.0-3.0dB 开销跌破 S&W 基准线
  Grace Period 生效: helper 成功 → 源端跳过 100 块重传

CA-CHARQ 领先的四大机制:
  1. Grace Period:    源端等待 helper → 跳过冗余重传
  2. 自适应 RV:       高置信时发 30 块(2.0s)代替 C-HARQ 90 块(6.0s)
  3. 中点竞争:        选出双向信道均衡的 helper
  4. 零退避:          高分数 (score>0.9) helper 立即发送

丢包率:
  所有协议在所有 SNR 下丢包率 = 0
  (MAX_HOP_RETRYS=5 足够覆盖所需重传)

十、PHY 层实现细节与文献对齐分析
================================================================================

本章逐一分析仿真中 Grace Period、MI、FEC/CRC/冗余合并的具体实现方式，
并与文献做法对比，评估精度水平。

10.1 Grace Period — 纯粹超时等待抽象
────────────────────
实现 (tx_loop 行 257-271):
    grace_to = self.env.timeout(grace_t)    # SimPy 超时事件
    ack_he   = simpy.Event(self.env)        # ACK 到达事件
    gr = yield grace_to | ack_he            # 谁先触发谁胜出

源端收到 NACK 后不立即重传，设置一个基于 Cpkt 估算的定时器
(2.0~6.0s + prop + 缓冲)，等待 helper 响应的 ACK。
若 ACK 先到 → 跳过源端重传；超时 → 源端重传。

简化了什么:
  真实 Grace Period 需要 MAC 层机制:
  - 源端检测 helper 已激活并正在传输
  - 预留信道时间 (NAV)
  - 处理潜在碰撞
  当前仿真将这一切抽象为"等待一个定时器"，忽略了信道侦听、
  退避协调、NAV 设置等复杂细节。

10.2 MI 计算 — Shannon 容量上限模型
────────────────────
实现 (handle 行 321):
    acc_mi = np.sum(np.log2(1.0 + soft_buffer[pid])) × BITS_PER_CHUNK
    if acc_mi >= TARGET_MI:   # 解码成功

直接使用 AWGN 信道 Shannon 容量公式: log2(1+SNR)。
这是理论上能达到的最大信道容量的近似，没有实际编码实现开销。

为什么用 Shannon 门限而非真实 BLER 曲线?
  (1) 协议级仿真的目标是对比不同协议的相对性能，不是预测绝对性能
  (2) 四种协议在同一 PHY 模型下竞争，公平性不受简化影响
  (3) 如果用真实 LDPC/Turbo 编解码，单次仿真时间增加 100-1000 倍，
      对协议研究的性价比极低

TARGET_MI=11000 与真实码字的对应:
  等效码率 = 8000/11000 ≈ 0.727
  这对应 3/4 码率 LDPC 的实际工作 SNR ≈ 2-3dB
  TARGET_MI 已下调以补偿真实码字与 Shannon 极限的 0.5-1.5dB 差距

10.3 FEC 编解码 — 完全信息论抽象
────────────────────
仿真中不存在实际的 FEC 编码器/解码器:

  (a) FEC 编码的体现:
      校验块 (RV1-3, Pac-1/Pac-2) 被建模为"在对应的 chunk 位上增加了
      新的 SNR 值"。RV 分片长度直接决定了 IR 增益的大小。

  (b) FEC 解码的体现:
      每一轮接收后对 soft_buffer 所有位置计算 Σ log2(1+SNR)。
      只要累积 MI 超过阈值 → 解码成功。没有逐比特译码、迭代过程、
      或收敛判断。

  (c) 码字性能差异:
      不同码字 (5G LDPC, Turbo, Polar) 的译码特性 (如误差地板、
      收敛速度、误码平层) 在此模型中无法体现。但这对协议对比
      影响可忽略——所有协议共享相同 PHY 抽象。

10.4 CRC 校验 — 不存在
────────────────────
  PhysicalPacket.header_ok 始终为 True。
  不存在 CRC 误检/漏检/包头损坏。
  这简化了 NACK/ACK 传输——当前无碰撞模型所以也不会丢包。

10.5 Chase 合并与 IR 合并
────────────────────
实现 (handle 行 312-319):
    if fec_idx > 0:            # C-HARQ FEC 包
        soft_buffer[fec区域]   += snr_array  (IR 合并)
    elif rv_level > 0:         # CA-CHARQ 校验包
        soft_buffer[start:end] += snr_array  (IR 合并)
    else:                      # RV0 系统数据
        soft_buffer[0:100]     += snr_array  (Chase 合并)

Chase 合并:
  物理意义上对应 MRC (最大比合并) 的线性加权求和。
  仿真中对相同 chunk 位置的 SNR 作线性相加 (soft_buffer += new_snr)。
  这是 MRC 的精确等效——合并后 SNR 等于各次接收 SNR 之和。

IR (增量冗余) 合并:
  物理意义上对应不同校验比特的联合迭代译码。
  仿真中将新校验块写入 soft_buffer 原先为零的空白位置，
  从而直接增加累积 MI。Shannon 模型正确捕获了 IR 提供
  "新信息"的本质效果——向空白位置增加独立的信息量。

 我们的仿真与 Ghosh 2013、Goutham 2021 在 PHY 抽象层次上完全一致。

 区别在于后者用预计算的 BLER 曲线查表 (基于先验链路仿真)，
 我们用实时 Shannon 容量计算——两者精度相当。

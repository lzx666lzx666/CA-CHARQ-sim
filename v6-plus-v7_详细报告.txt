执行摘要
──────────────────────────────────────────────────────────────
v7 是 v6-plus 系列的定型版本。PHY 层使用 3GPP NR 标准的 MIESM 
(Mutual Information Effective SINR Mapping) 方法，结合 Shannon 
容量与实用编码差距 (gap_db) 的解析 BLER 模型。解码判据和 Cpkt 
置信度计算均基于 MIESM 指标，彻底移除了早期版本的 Shannon MI 
绝对值 (TARGET_MI=11000) 依赖。

v7 的核心创新在于竞争机制的分层 fallback 设计：高置信 (cpkt>=3) 
时全 helper 竞争 (含零退避优化)；低置信时瓶颈最优 helper 近零退避 
(0.02s) 首发，其余 helper 正常竞争后备——在消除单点故障的同时最小化
竞争调度开销。

二、MIESM PHY 层 (两个核心函数)
================================================================================

2.1 miesm_confidence(soft_buffer) — Cpkt 计算
────────────────────────────────────
  输入: soft_buffer (190 维累加 SNR 向量)
  输出: (delta_db, cpkt)

  流程:
    1. avg_mi = mean(log2(1+SNR_i)) over active chunks
    2. SNR_eff_db = 10×log10(2^avg_mi − 1)
    3. code_rate = 100 / n_active
    4. snr_shannon_db = 10×log10(2^code_rate − 1)
    5. gap_db = 2.5 − code_rate
    6. snr_50_db = snr_shannon + gap_db
    7. delta_db = SNR_eff − snr_50
    8. Cpkt 阈值:
         delta > −0.2  → cpkt=3  (高置信, Grace 触发)
         delta > −2.0  → cpkt=2  (中置信)
         delta > −3.5  → cpkt=1  (低置信)
         否则          → cpkt=0  (极低置信)

  delta_db ≈ −1.5 时对应 BLER ≈ 95% (0 dB, 仅 RV0)
  delta_db ≈  0.0 时对应 BLER ≈ 50%
  delta_db ≈  2.0 时对应 BLER ≈ 0.01%

2.2 compute_packet_per(soft_buffer) — PER (解码失败概率)
────────────────────────────────────
  流程: 同 miesm_confidence 的第 1-6 步, 然后:
    bler = sigmoid(4.0 × (SNR_eff_db − snr_50_db))
    return bler

  关键: 解码成功判据为 random() > bler (概率型), 不再是
       确定型 MI 门限。

2.3 与 3GPP NR MIESM 对应关系
────────────────────────────────────
  3GPP NR 手法            v7 实现
  ─────────────────────────────────────────
  逐子载波 SINR→I(SINR)    逐 chunk log2(1+SNR)
  平均 MI→SNR_eff           avg_mi→SNR_eff
  查 BLER 表(MCS 相关)     解析 sigmoid(code_rate)
  不同 RV→不同 MCS          不同 n_active→code_rate

  差异: 3GPP 用预计算 BLER 表, v7 用解析 sigmoid 近似。
       两者在 SNR-BLER 的 S 形建模上是等价的。

三、四协议逻辑详述
================================================================================

3.1 S&W ARQ
────────────────────
  无 helper。源端发送 RV0 → 目的端 MIESM PER → 失败则 NACK (一次)
  → 源端 RV0_retry (Chase) → 累加 soft_buffer → 重算 PER。
  延迟最大, 开销最低。

3.2 C-ARQ
────────────────────
  每跳 1 个预选 helper (距中点最近)。源端发 RV0 + helper 发 RV0。
  目的端纯 Chase 合并。无 IR 增益。

3.3 C-HARQ
────────────────────
  每跳 1 个预选 helper。源端发 RV0 + helper 听到 NACK 后
  主动连发 Pac-1(50 块) + Pac-2(40 块)。目的端 Chase+IR 合并。

3.4 CA-CHARQ (核心协议)
────────────────────

  (a) 解码与 Cpkt: 均基于 MIESM, 无 Shannon MI 依赖。

  (b) 源端 tx_loop:
      - 发送 RV0, 等待 ACK/NACK/超时 (gto=7.3s)
      - 收到 NACK(Cpkt≥3) → Grace Period:
        Grace_t = rv_tx_t + T_MAX_WINDOW/4 + 3×prop + 0.3s
        等待 helper ACK (ack_he) 或超时
        ACK 先到 → hop_ok (跳过源端重传)
        超时 → 源端发 RV0_retry
      - Cpkt<3 → 无 Grace → 源端直接 RV0_retry

  (c) 目的端 NACK:
      - 仅对源端数据 (hop_tx==hop_source) 发送 NACK_cpkt
      - nack 上限条件化: cpkt≥3 时 3 次, 否则 1 次

  (d) Helper 竞争 (contend):
      得分公式:
        d_bneck = max(dist_to_source, dist_to_dest)  ← 瓶颈距离
        score = 0.40×min(c_pkt,1.5) + 0.25×energy/INIT
                + 0.35/(1+prop_bneck/0.4s)

      退避分层 fallback:
        - score > 0.90 → t = 0 (零退避)
        - cpkt < 3 && is_low_snr_selected → t = 0.02s (瓶颈最优首发)
        - 其余 → t = (1−score)×T_MAX_WINDOW×2 + 0.05s

      竞争取消: 其他 helper 收听到获胜者对该链路数据包
                → 触发 cancel_event → 退让。

      获胜 helper 发送自适应 RV:
        cpkt≥2 → RV1 (30 块, 2.0s)  cpkt=1 → RV2 (60 块)
        cpkt=0 → RV3 (90 块)

  (e) 低 SNR 预选 (is_low_snr_selected):
      在 run_sim 中用瓶颈距离 max(d_src, d_dst) 预选最优 helper,
      用于 cpkt<3 时的首发优先权。

  (f) Grace ACK 触发:
      源端收到 ACK 时检查 helper_ack_events[pid] → 触发 Grace 成功。

四、信道模型与拓扑
================================================================================

4.1 信道模型
────────────────────
  TL(d) = d_km^1.5 × 10^(0.04×d_km)
  noise_var = TX_POWER_W / (TL × SNR_linear)
  Rician K=2 块级衰落: I = los+N(0,1)×nlos, Q similar
  SNR_chunk = asnr × (I²+Q²)

4.2 拓扑
────────────────────
  路由器: 节点 0→1→2→3→4→5, x=i×600m, y=0
  Helper: 每跳 3 个, 随机分布在源-目的圆交叠区域
  C-HARQ/C-ARQ: 预选中点最近者
  CA-CHARQ: 额外预选瓶颈距离最优者 (is_low_snr_selected)

4.3 仿真参数
────────────────────
  SNR: 0.0~4.0 dB, 0.5 步长, 共 9 点
  SIM_TIME: 15000s, N_RUNS: 5 次 MC
  发包: 指数分布 exp(30s), ~500 包/协议

5.3 结果解读
────────────────────
  (a) CA-CHARQ 延迟在 0-3.0 dB 全域领先 C-HARQ。
      0 dB: 69s vs 73s (−5%)
      2.0 dB: 51s vs 56s (−9%)

  (b) CA-CHARQ 开销在 0 dB 与 C-HARQ 在统计范围内持平
      (14.27 ± 0.65 vs 13.76 ± 0.69, CI 重叠)。
      0.5 dB+ 逐渐与 C-HARQ 拉开距离, 3.0 dB+ 低于 S&W。

  (c) 0 dB 处开销略高的结构性原因:
      - C-HARQ 发 Pac-1(50)+Pac-2(40)=90 块无条件发送
      - CA-CHARQ 发 RV1(30 块), 但竞争分层 fallback 的
        SimPy 事件调度存在 ~10 块/跳的额外开销
      - 差异 0.51 位于 CI 范围内, 统计意义上无显著差异

  (d) 收敛在 3.5-4.0 dB, 全程丢包率 = 0。

六、v7 相对于 v6 的关键改进
================================================================================

  1. 瓶颈距离竞争: d_bneck = max(d_src, d_dst)
     → 选出双向信道均衡的 helper

  2. 分层 fallback 退避:
     cpkt<3 时瓶颈最优 helper 0.02s 首发 (省去全竞争调度)
     其余 helper 正常后备 (消除单点故障)

  3. NACK 上限条件化:
     cpkt≥3 时 3 次, 否则 1 次
     → Grace 不激活时避免无效 NACK

  4. 统一 Grace_t 公式 (T_MAX_WINDOW/4 + 3×prop + 0.3)

二、MIESM PHY 层解码模型（v5 核心新增）
================================================================================

2.1 设计原理
────────────────────
v3 使用 Shannon 容量公式直接判断:
    acc_mi = Σ log2(1+SNR_i) × 80 ≥ TARGET_MI → 成功

v5 替换为 3GPP NR 标准的 MIESM 流程:
    Step 1: 逐 chunk 计算每位 MI:  mi_i = log2(1+SNR_i)
    Step 2: 平均 MI:              avg_MI = mean(mi_i)
    Step 3: 逆映射到有效 SNR:     SNR_eff = 2^avg_MI - 1
    Step 4: 码率计算:             code_rate = 100 / n_active
    Step 5: 参照 SNR:             SNR_50 = Shannon_SNR(R) + gap(R)
    Step 6: BLER 判决:            BLER = sigmoid(SNR_eff, SNR_50)

2.2 compute_packet_per() 实现
────────────────────
    def compute_packet_per(soft_buffer):
        active = soft_buffer > 0
        n_active = sum(active)
        if n_active < 100: return 1.0

        mi_per_chunk = log2(1.0 + soft_buffer[active])
        avg_mi = mean(mi_per_chunk)
        snr_eff_db = 10 × log10(2^avg_mi − 1)

        code_rate = 100.0 / n_active
        snr_shannon_db = 10 × log10(2^code_rate − 1)
        gap_db = 2.5 − code_rate
        snr_50_db = snr_shannon_db + gap_db

        bler = 1.0 / (1.0 + exp(4.0 × (snr_eff_db − snr_50_db)))
        return clip(bler, 1e-8, 1−1e-8)

2.3 MIESM 三大增益来源
────────────────────
  (a) Chase 合并:
      SNR 翻倍 → avg_MI 提升 ≈ 1 bit/chunk → SNR_eff_db 提升 ≈ 3 dB
      → BLER 从 0.998 降到 0.002

  (b) IR (增量冗余):
      avg_MI 不变，但 code_rate 从 1.0 降到 0.77
      → SNR_shannon 从 0 dB 降到 −1.5 dB
      → SNR_50 从 1.5 dB 降到 0.2 dB
      → BLER 从 0.998 降到 0.70

  (c) 好信道 helper:
      helper 在中点处 SNR ≈ 4.6 dB (vs 0 dB 的源-目的链路)
      → parity chunk 的 avg_MI 更高 → 拉高整体 avg_MI
      → SNR_eff 提升 → BLER 进一步降低

2.4 关键预计算（0 dB 链路 SNR）
────────────────────
 场景                 n_chunks  avg_MI  SNR_eff  code_rate  SNR_50  BLER
 ─────────────────────────────────────────────────────────────────────
 1×RV0                100       1.00    0.0 dB   1.000      1.5 dB  0.998
 2×RV0 (Chase)        100       1.59    3.0 dB   1.000      1.5 dB  0.002
 1×RV0 + RV1(中点)    130       1.18    1.1 dB   0.769      0.2 dB  0.034
 1×RV0 + Pac-1(中点)  150       1.27    1.5 dB   0.667     −0.5 dB  0.0004

2.5 与 3GPP NR MIESM 的对应关系
────────────────────
 3GPP NR MIESM                     v5 实现
 ────────────────────────────────────────────────────────
 逐子载波 SINR → I(SINR_i)        逐 chunk log2(1+SNR_i)
 平均 MI → SNR_eff                 平均 MI → SNR_eff
 查 AWGN BLER 表 (MCS 相关)       sigmoid 参数公式 (code_rate)
 不同 RV 对应不同 MCS              不同 n_active 对应 code_rate

 差异: 3GPP 使用预计算的 BLER 查找表（需链路仿真生成），
       v5 使用基于 Shannon 容量 + 实用差距的解析公式近似。
       两者在 SNR→BLER 的 S 形曲线建模上是等价的。

四、协议逻辑详述
================================================================================

四协议框架完全继承 v3，仅 PHY 判据从 MI 门限改为 MIESM PER。

4.1 S&W ARQ
────────────────────
  源端发 RV0 → 目的端 MIESM PER → 随机判决
  BLER 高 → NACK (一次) → 源端 RV0_retry → Chase 合并 → 重算 PER

4.2 C-ARQ
────────────────────
  源端发 RV0 + 预选 helper 发 RV0
  目的端对双路 RV0 做 Chase 合并 → 重算 PER

4.3 C-HARQ
────────────────────
  源端发 RV0 + 预选 helper 发 Pac-1(50 块) + Pac-2(40 块)
  目的端: 源 RV0 Chase + Pac-1 IR + Pac-2 IR → 降低 code_rate → 重算 PER

4.4 CA-CHARQ
────────────────────
  全部 v3 机制保留:
  - 置信度量化 (confidence_quantize): 用于 Cpkt 计算
  - 退避竞争 (contend): 中点距离基准, 零退避(score>0.9)
  - Grace Period: 仅 Cpkt≥3 启用
    Grace_t = rv_tx_t + T_MAX_WINDOW/4 + 3×prop + 0.3s
  - 自适应 RV: 仅发校验块 (RV1-3)
  - NACK 仅对源端数据触发 (hop_tx == hop_source)

4.5 helper 竞争得分公式
────────────────────
  score = 0.40 × min(c_pkt, 1.5)
        + 0.25 × max(0, min(1, energy/INITIAL))
        + 0.35 / (1 + prop_to_midpoint/0.4s)

  退避: t = (1−score)×T_MAX_WINDOW×2 + 0.05
       若 score > 0.90 → t = 0

6.3 结果解读
────────────────────
  (a) CA-CHARQ 在 0-3.0 dB 全域延迟领先
      - 0 dB: 69s vs C-HARQ 74s (−7%)
      - 2.0 dB: 49s vs C-HARQ 56s (−12%)
      - 差异来源: MIESM 捕获了 helper 好信道 (中点 4.6 dB) 对 avg_MI 的提升

  (b) Grace Period 仅在 Cpkt≥3 启用
      - 0 dB: Cpkt≈2 → Grace 跳过 → 与 v3 一致 (72s 附近)
      - 1.5 dB+: Cpkt=3 → Grace 激活 → 开销下降

  (c) 开销在 2.5 dB+ 低于 S&W
      Grace 成功 → 源端跳过一次 RV0 重传 → 节省 100 块开销

  (d) 收敛在 ~3.5-4.0 dB
      与 v3 的 0-4 dB 过渡区间一致

  (e) 丢包率: 全部 0%
      MAX_HOP_RETRYS=5 覆盖所有重传需求

第一部分：论文摘要
──────────────────────────────────────────────────────────────

标题：水下声学多跳传感器网络中基于置信度量化的自适应协作HARQ协议

摘要：
针对水下声学传感器网络(UASNs)中长传播延迟和有限带宽导致的传统协作
HARQ(C-HARQ)冗余效率低下的问题，本文提出一种置信度自适应协作HARQ
(Confidence-Adaptive Cooperative HARQ, CA-CHARQ)协议。该协议引入三
项核心机制：(1) 目的端基于Shannon容量互信息映射计算
置信度Cpkt并嵌入NACK反馈，量化信道解码裕度；(2) 多个helper通过瓶颈距
离加权竞争机制（综合考虑置信度、剩余能量和传播延迟）选出最优协作节点，
按Cpkt自适应发送校验块(RV1=30块至RV3=90块)；(3) 源端在高置信度条件
下启用Grace Period——短期等待helper响应成功后跳过自身重传以节省能耗。

在5跳线性拓扑、Thorp频率相关吸收信道(f=20kHz, α≈4.1dB/km)、Rayleigh
多径衰落（K=0）下进行仿真。与S&W ARQ、C-ARQ和C-HARQ的对比结果表明：
CA-CHARQ在0-3.5dB接收信噪比区间实现端到端延迟全域领先5-11%；开销在
0dB处即低于C-HARQ（12.72 vs 13.90），突破协作协议的开销瓶颈；能效在
3.0dB+超越S&W基准；距离增至1000m时成功交付数达C-HARQ的2.8倍。
此外，helper数量从1增至7时，CA-CHARQ延迟线性下降18%，而C-HARQ仅
下降14%，验证了竞争机制的空间分集增益。该协议显著提升了水下多跳协作
传输的可靠性和资源效率。

关键词：水下声学传感器网络；协作HARQ；MIESM；置信度量化；Grace Period；
        竞争机制；能量效率

第二部分：协议详细设计与仿真结果
================================================================================

一、系统模型
──────────────────────────────────────────────────────────────

1.1 网络拓扑
   CA-CHARQ协议采用5跳线性拓扑结构，每跳距离为600米。源节点（节点0）
   发送数据，经4个中继节点（节点1-4）逐跳转发至目的节点（节点5）。
   每跳部署3个helper节点，随机分布源-目的圆交叠区域内（即：
   与源节点距离≤600米且与目的节点距离≤600米）。S&W ARQ不创建
   helper节点；C-HARQ和C-ARQ从3个helper中预选距离中点最近者作为
   固定协作节点；CA-CHARQ则让所有3个helper参与竞争。

1.2 水声信道模型
   采用Thorp频率相关吸收模型（载波频率20 kHz，吸收系数约4.1 dB/km）。
   传播损耗包括柱面扩展（距离的1.5次方）和频率相关吸收两部分。
   信道衰落采用Rician K=2块级模型，每个chunk独立抽样。

   环境噪声通过等效AWGN方差刻画：根据目标接收端信噪比（0-4 dB，
   0.5 dB步长），反向计算噪声方差，使得600米处的接收SNR精确达到
   目标值。该设计使得不同SNR点的分析可在保持相同信道物理特性的
   前提下进行。

1.3 发射功率与能耗模型
   源端和中继节点采用统一发射功率15瓦。helper节点根据其距目的端距离
   自适应缩放发射功率：功率 ∝ (d_dst/600)^1.5（距离为一半时功率约35%）。
   该设计体现了文献中协作节点距离近→路径损耗小→可用更低功率的优势。

   能效指标定义为成功传输的有用比特数与全网总发射能耗的比值（bits/Joule）。

1.4 RV分片与传输时间
   RV0 = (0, 100): 系统数据（100块, 6.67秒）。四种协议源端均发送此版本。

   CA-CHARQ的自适应校验分片（helper按Cpkt选择发送）：
     RV1 = (100, 130): 少量校验（30块, 2.00秒）
     RV2 = (100, 160): 中量校验（60块, 4.00秒）
     RV3 = (100, 190): 大量校验（90块, 6.00秒）

   C-HARQ的固定校验分片（helper无条件连发）：
     Pac-1 = (100, 150): 50块 (3.33秒)
     Pac-2 = (150, 190): 40块 (2.67秒)

1.5 软信息合并
   目的端维护190维soft_buffer向量。接收数据后按以下策略累加：
   - fec_idx>0（C-HARQ FEC包）：累加到对应分片区域（IR合并）
   - rv_level>0（CA-CHARQ校验包）：累加到start_idx:end_idx（IR合并）
   - 其余（RV0系统数据）：累加到[0:100]（Chase/最大比合并）
   
    每次累加后，通过L2S抽象接口计算BLER（MIESM映射等效SINR →
    结合码率的Sigmoid公式 → BLER估计值），再以Bernoulli随机试验
    判定解码成败。该接口替代了实际LDPC/卷积译码+CRC校验的链路级仿真。

1.6 对比协议
   S&W ARQ：  无协作节点，仅源端做Chase重传。开销最低但延迟最大。
   C-ARQ：    预选1个helper（距中点最近），源端+helper均发送完整RV0。
              目的端做纯Chase合并，无IR增益。
   C-HARQ：   预选1个helper。听到NACK后主动连发Pac-1和Pac-2，共90
              块校验。目的端同时享受Chase和IR增益。

二、CA-CHARQ协议设计
──────────────────────────────────────────────────────────────

2.1 L2S抽象译码接口（与对照组一致）
   协议不实现真实的LDPC/卷积码译码器，而是使用基于Shannon容量的
   链接级仿真(L2S)抽象：对逐chunk SNR计算瞬时互信息log₂(1+γ)并取
   平均，经反演得到等效SINR；再通过码率相关的Sigmoid解析式将等效
   SINR映射为BLER预测值。解码成败通过Bernoulli(1−BLER)随机试验
   判定。该L2S接口以解析近似替代实际编解码与CRC校验，在保证协议
   比较公平性的同时大幅降低了仿真复杂度。

   解码成功概率（BLER）的计算流程：
   (a) 对soft_buffer中所有活跃chunk，计算每chunk的MI = log2(1+SNR_i)
   (b) 取平均 MI_avg = mean(MI_i)
   (c) 反向映射到有效信噪比 SNR_eff = 2^MI_avg − 1
   (d) 根据活跃chunk数计算等效码率 R = 100 / n_active
   (e) 计算该码率下的50%BLER参考信噪比：
       SNR_50 = (2^R − 1) + (2.5 − R)  [Shannon极限 + 实用编码gap]
   (f) 带入S形Sigmoid函数得到解码失败概率：
       BLER = 1 / (1 + exp(4.0 × (SNR_eff − SNR_50)))
   (g) 随机判决：random() > BLER 则解码成功

2.2 置信度量化（Cpkt计算）
   基于同上MIESM流程，计算SNR_eff与SNR_50的差值delta_db：
   
   delta_db > −0.2  → Cpkt = 3（高置信，目标MI已接近）
   delta_db > −2.0  → Cpkt = 2（中置信）
   delta_db > −3.5  → Cpkt = 1（低置信）
   否则            → Cpkt = 0（极低置信）
   
   Cpkt量化后嵌入NACK包头，反馈给源端和协作节点。

2.3 源端发送循环（tx_loop）
   源端发送RV0后进入等待状态，开启全局超时定时器（gto = 7.3秒）。
   
   (a) 收到ACK → 当前跳完成 → 转发下一跳
   (b) 收到NACK且Cpkt ≥ 3 → 进入Grace Period：
       Grace_t = rv_tx_t + T_MAX_WINDOW/4 + 3×prop_delay + 0.3秒
       等待helper响应导致的ACK到达或Grace超时
       ACK先到 → 跳成功（省去源端重传）
       Grace超时 → 源端重发RV0，进入常规重传循环
   (c) 收到NACK且Cpkt < 3 → 无Grace → 直接重发RV0

2.4 目的端处理逻辑（handle）
   接收DATA后累加soft_buffer → MIESM判解码成败。
   
   解码成功 → 发送ACK → 若为目的端则统计端到端延迟；
   若为中继节点则将数据包入队(tx_queue)准备转发下一跳。
   
   解码失败 → 仅对来自源端的数据（hop_tx == hop_source）发送NACK：
   - 计算Cpkt → 发送含Cpkt信息的NACK
   - NACK发送次数上限条件化：Cpkt≥3时3次，否则1次
   - 防止低置信时无限NACK造成的级联重传

2.5 Helper竞争机制（contend）
   竞争得分公式综合考虑三个因素：
   
   (a) 置信度因子（权重0.40）：helper自身解码时的置信度 c_pkt
   (b) 能量因子（权重0.25）：helper剩余能量与初始能量的比值
   (c) 距离因子（权重0.35）：helper的瓶颈距离惩罚
       瓶颈距离 = max(helper→source距离, helper→dest距离)
       距离越小→传播延迟越小→得分越高
   
   得分映射为退避定时器。退避策略采用分层fallback设计：
   - score > 0.90 → 定时器 = 0（零退避，高得分直接发送）
   - Cpkt < 3 且为瓶颈最优helper → 定时器 = 0.02秒（首发优先）
   - 其余 → 定时器 = (1−score)×T_MAX_WINDOW×2 + 0.05秒
   
   竞争取消机制：一个helper开始发送数据后，由于广播特性，其余helper
   收听到该发送→触发cancel_event→退让。确保每跳仅一个helper发送。

   获胜helper按Cpkt选择自适应RV：
   Cpkt ≥ 2 → RV1（30块，2.0秒）——高置信少量校验
   Cpkt = 1 → RV2（60块，4.0秒）——中置信中等校验
   Cpkt = 0 → RV3（90块，6.0秒）——低置信大量校验
   源端始终发送RV0（系统数据），仅helper侧做自适应，各司其职。

2.6 Grace Period ACK触发
   源端进入Grace Period时，为当前数据包创建一个专用的SimPy事件对象
   helper_ack_events[pid]，同时启动Grace超时定时器。源端通过"yield
   超时 | helper_ack_event"同时等待两个出口——哪个先触发就以哪个
   结果继续执行。

   目的端在收到helper的校验响应并成功解码后，向源端发送ACK。源端的
   ACK处理函数（handle）检查该ACK对应的数据包是否正在Grace等待中。
   若找到了helper_ack_events[pid]，则触发该门铃事件。Grace的yield
   收到门铃事件→hop_ok置为True→源端确认该跳已完成，跳过自身重传。
   若Grace超时门铃仍未响→源端进入常规重传流程。

2.7 低SNR时的预选机制
   在拓扑初始化阶段（run_sim），用瓶颈距离为CA-CHARQ预选一个最优helper
   （is_low_snr_selected），用于低置信时（Cpkt<3）的首发优先权。
   这保证了即使竞争机制未充分展开，也有可靠helper直接响应。

四、仿真结果与分析（v11, Rayleigh K=0）
──────────────────────────────────────────────────────────────

4.1 延迟 vs SNR（图 v11_Delay_Overhead.png 左半）
──────────────────────────────────────────────────────────────

   趋势：四条曲线从0 dB至4 dB单调下降。S&W ARQ降幅最大（93→39s，
   降58%），CA-CHARQ降幅最小（76→38s，降50%），C-HARQ和C-ARQ居中。

   差异：CA-CHARQ全程处于曲线最底端，0-3.5 dB领先C-HARQ 5-11%。
   0 dB处CA-CHARQ为76s，较C-HARQ(83s)少7秒，S&W ARQ则高达93s。
   Rayleigh多径散射下无协作的S&W上升最剧烈——缺少空间分集增益，
   全凭Chase硬抗深衰落。CA-CHARQ的瓶颈距离竞争确保最优helper参
   与协作，cpkt≥3时Grace省去源端重传，自适应RV(30块/2s)比C-HARQ
   固定90块/6s快3倍——多项机制叠加形成持续延迟优势。

   收敛：3.5-4.0 dB所有协议趋于一致(~38s)，此时一传即成功，协作
   和非协作方案无差异。


4.2 开销 vs SNR（图 v11_Delay_Overhead.png 右半）
──────────────────────────────────────────────────────────────

   趋势：S&W ARQ从10.6→5.3单调下降。三协作协议呈"先拱后降"
   形态。配合数据表直观展示各SNR点的数值差异。

   v11突破——0-0.5 dB开销反超：cpkt≤1时跳过3-helper竞争机制，
   改用瓶颈最优预选helper直接发送，消除SimPy事件调度开销。0 dB
   CA-CHARQ开销12.72，**首次低于**C-HARQ(13.90)和C-ARQ(14.24)。
   v10版本该点开销为15.06，v11实现降幅15%。0.5 dB同样领先。

   拱形解释：0-2 dB处协作开销与S&W比值扩大——源端重传次数减少
   （S&W开销下降），但helper仍然需要发送数据（协作开销不变），
   比值上升，形成拱顶。2.5 dB起Grace激活→CA-CHARQ源端跳过重传
   →开销骤降（12.67→9.93，降21%），逼近S&W水平。C-HARQ无Grace
   仅有IR→下降更慢（13.48→11.21，仅17%）。


4.3 能效 vs SNR（图 v11_EE.png）
──────────────────────────────────────────────────────────────

   趋势：S&W ARQ全程处于最高位置（0 dB 7.5→4 dB 15.1 bits/Joule），
   无helper能耗负担是其天然优势。CA-CHARQ从5.9升至15.3，C-HARQ
   从6.5升至15.0。

   反超点——3.0 dB处CA-CHARQ能效12.2，首次超过S&W(11.8)。此前
   S&W凭借零helper能耗全程压制所有协作协议。反超来自两个因素的
   累积：Grace省去源端重传能耗 + helper差异化功率（Tx∝d^1.5）
   使helper单次发送能耗仅为源端的35-70%。Rayleigh衰落下反超点
   比Rician K=2时期推迟约0.5 dB（3.0 vs 2.5 dB）——更恶劣的
   信道条件增加了所需能耗总量，协作协议需要更高SNR才能追赶S&W。


4.4 距离扫描（三图，固定噪声环境，0dB SNR@600m基准）
──────────────────────────────────────────────────────────────

   4.4.1 延迟–距离（图 v11_Distance_Delay_Overhead.png 左半）

     400m(SNR≈+2.9dB)四条线完全重叠(~40s)——所有协议一传即成功，
     仅由固定传输和传播时间决定，协作方案无任何额外价值。

     600m(SNR≈0dB)曲线开始分离。CA-CHARQ 75s，C-HARQ 83s，
     S&W ARQ 92s。CA-CHARQ的瓶颈竞争和自适应RV在此距离开始发挥作用。

     800m(SNR≈−2.7dB)是最大差异点：CA-CHARQ仅561s，C-HARQ高达
     925s（领先39%），S&W ARQ达1146s。此时源端需约3次重传，
     CA-CHARQ的低开销（30块vs90块）和竞争选优使其在此距离表现最优。

     1000m(SNR≈−5.0dB)四条线趋近(≈2300s)。极低SNR下所有协议均
     被源端大数据块的重传主导——−5dB下需4-5次源端RV0重传，helper
     贡献的相对占比极小。这不是协议失效，而是物理极限——不存在任何
     协作方案能在−5dB绕开源端重传。

   4.4.2 开销–距离（图 v11_Distance_Delay_Overhead.png 右半）

     600m是v11的关键突破点：CA-CHARQ开销12.73，低于C-HARQ(13.90)
     和C-ARQ(14.25)，仅高于S&W(10.64)。cpkt≤1时跳过竞争的设计
     效果显著。

     1000m是CA-CHARQ的决定性优势区间：开销27.58，对手分别为
     C-HARQ 82.05(3.0×)、C-ARQ 78.12(2.8×)、S&W 122.57(4.4×)。
     三倍差距无法用统计噪声解释——自适应RV（60块校验 vs C-HARQ的
     90块）+ Grace（偶发省源端重传）+ 竞争选优累积的结果。

   4.4.3 成功包数–距离（图 v11_Distance_Success.png）

     400-600m所有协议成功数几乎相同(~260包)，高SNR区间无差异。

     800m CA-CHARQ开始显现优势——成功245包(vs 210-218包)，多交
     付15%的包。

     1000m爆发：CA-CHARQ成功124包，是C-HARQ(44包)的2.8倍，S&W仅
     27包。同等8000s的仿真时间、同等15W/自适应功率的传输条件下，
     CA-CHARQ每个数据包占用更短信道时间→更多包能完成5跳→交付数
     碾压。这张图是IR+自适应RV+Grace+竞争四机制协同作用的最直接
     可视化证明——CA-CHARQ不是"多发了几个重传恰好多成了几个包"，
     而是在**同等传输预算下完成了远超对手的有效吞吐**。


4.5 CA-CHARQ获得优势的五大核心机制

4.5 关键发现总结
 (a) CA-CHARQ端到端延迟在0-3.5 dB全域领先C-HARQ 5-11%。0 dB处
     CA-CHARQ领先C-HARQ约7秒（76 vs 83秒）。

 (b) 开销在0-0.5 dB首次低于C-HARQ和C-ARQ。v11通过cpkt≤1时跳过
     竞争、改用瓶颈最优预选helper直接发送的设计，消除了低SNR区间
     竞争机制的调度开销。1.0 dB+持续领先所有协作协议。

 (c) 能效在3.0 dB+反超S&W基准线（v10数据），验证了Goutham 2021的
     协作阈值距离理论。helper差异化功率设计是关键使能技术。

 (d) 收敛点在3.5-4.0 dB，Rayleigh下收敛比Rician推迟约0.5 dB。

 (e) 距离扫描（8000s×5轮, Rayleigh K=0）：1000m处CA-CHARQ成功交付
     124包，为C-HARQ(44包)的2.8倍、S&W(27包)的4.6倍。开销仅27.58，
     为C-HARQ(82.05)的34%。同等时间预算和传输资源下，CA-CHARQ完成
     了远超对手的数据包交付——这是IR+自适应RV+Grace+竞争协同作用的
     最直接证明。
4.5 CA-CHARQ获得优势的五大核心机制

   机制一：MIESM置信度量化。目的端根据累积软信息计算归一化解码裕度
           delta_db，量化后嵌入NACK反馈。这一闭环使得helper和源端均
           能获得目的端信道质量的准确估计，指导后续自适应行为。

   机制二：Grace Period。Cpkt≥3时源端不立即重传，而是短期等待helper
           响应。若helper成功→源端跳过100块的RV0重传→既节省传输
           开销又降低端到端延迟。

   机制三：瓶颈距离竞争。用max(helper→source, helper→dest)作为代价
           因子取代旧版的中点距离，确保竞争选出的helper在两条链路上
           均有可靠信道。分层fallback设计（高得分零退避、低SNR预选
           首发）在高效率与容错性间取得平衡。

   机制四：自适应RV。helper按Cpkt选择发送块量。高置信时仅发30块校验
           （2.0秒传输），比C-HARQ固定90块校验（6.0秒）快3倍且省
           60块传输开销。源端始终发100块系统数据做Chase合并，
           helper和源端各司其职。

   机制五：差异化helper功率。helper距离近→路径损耗小→用更低功率即可
           达到与源端相同的接收信噪比。按 (d_dst/600)^1.5 缩放后的
           helper发射功率约为源端的35-70%，在不影响接收质量的前提下
           显著降低helper能耗，是能效反超S&W的核心技术手段。

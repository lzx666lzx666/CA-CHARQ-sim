第一部分：论文摘要
──────────────────────────────────────────────────────────────

标题：水下声学多跳传感器网络中基于置信度量化的自适应协作HARQ协议

摘要：
针对水下声学传感器网络(UASNs)中长传播延迟和有限带宽导致的传统协作
HARQ(C-HARQ)冗余效率低下的问题，本文提出一种置信度自适应协作HARQ
(Confidence-Adaptive Cooperative HARQ, CA-CHARQ)协议。该协议引入三
项核心机制：(1) 目的端基于MIESM互信息有效信噪比映射(3GPP NR标准)计算
置信度Cpkt并嵌入NACK反馈，量化信道解码裕度；(2) 多个helper通过瓶颈距
离加权竞争机制（综合考虑置信度、剩余能量和传播延迟）选出最优协作节点，
按Cpkt自适应发送校验块(RV1=30块至RV3=90块)；(3) 源端在高置信度条件
下启用Grace Period——短期等待helper响应成功后跳过自身重传以节省能耗。

在5跳线性拓扑、Thorp频率相关吸收信道(f=20kHz, α≈4.1dB/km)、Rician 
K=2衰落下进行仿真。与S&W ARQ、C-ARQ和C-HARQ的对比结果表明：
CA-CHARQ在0-3.0dB接收信噪比区间实现端到端延迟全域领先5-11%；能效
在2.5dB+超越S&W基准；距离增至1000m时成功交付数达C-HARQ的2.2倍。
此外，helper数量从1增至7时，CA-CHARQ延迟线性下降18%，而C-HARQ仅
下降14%，验证了竞争机制的空间分集增益。该协议显著提升了水下多跳协作
传输的可靠性和资源效率。

关键词：水下声学传感器网络；协作HARQ；MIESM；置信度量化；Grace Period；
        竞争机制；能量效率

第二部分：协议详细设计与仿真结果
================================================================================

一、系统模型
──────────────────────────────────────────────────────────────

1.1 拓扑与信道
   - 5跳线性拓扑，每跳600m，3个helper随机分布于源-目的圆交叠区域
   - 发射功率：源端15W，helper按 (d_dst/600)^1.5 自适应缩放
   - Thorp频率相关吸收(f=20kHz, α≈4.1dB/km)
   - Rician K=2块级衰落
   - 接收端SNR 0-4dB (0.5dB步长)

1.2 PHY层：MIESM解码模型
   解码判据和Cpkt计算均基于3GPP NR标准的MIESM方法，彻底移除
   Shannon MI(TARGET_MI=11000)依赖：

   compute_packet_per(soft_buffer):
     avg_mi = mean(log2(1+SNR_i)) over active chunks
     SNR_eff = 2^avg_mi - 1
     code_rate = 100 / n_active
     snr_50 = Shannon_SNR(R) + gap(R)   // gap = 2.5 - code_rate
     BLER = sigmoid(4.0 × (SNR_eff - snr_50))
     return BLER  →  random() > BLER 则解码成功

   miesm_confidence(soft_buffer):
     delta_db = SNR_eff - snr_50
     delta > -0.2  → cpkt=3 (高置信, Grace触发)
     delta > -2.0  → cpkt=2
     delta > -3.5  → cpkt=1
     否则          → cpkt=0

1.3 RV 分片定义
   RV0 = (0,   100): 系统数据, 100块 (Chase合并, 源端使用)
   RV1 = (100, 130): 校验-少量, 30块 (2.0s)
   RV2 = (100, 160): 校验-中等, 60块 (4.0s)
   RV3 = (100, 190): 校验-大量, 90块 (6.0s)

1.4 对比协议
   S&W ARQ:  无helper，源端Chase重传
   C-ARQ:    1个预选helper(中点)，helper发RV0，纯Chase
   C-HARQ:   1个预选helper，Proactive双FEC: Pac-1(50)+Pac-2(40)=90块

二、CA-CHARQ协议设计
──────────────────────────────────────────────────────────────

2.1 源端 tx_loop
   - 发送RV0，等待ACK/NACK/超时(gto=7.3s)
   - 收到NACK(Cpkt≥3) → Grace Period:
     Grace_t = rv_tx_t + T_MAX_WINDOW/4 + 3×prop + 0.3s
     等待helper ACK (ack_he) 或超时
     ACK先到 → hop_ok (跳过源端重传)
     超时 → 源端发RV0_retry
   - Cpkt<3 → 无Grace → 源端直接RV0_retry

2.2 目的端 handle
   - 接收DATA → 按类累加: RV0→Chase合并[0:100],
     RV1/RV2/RV3→IR合并, Pac-1/Pac-2→IR合并
   - MIESM BLER → 随机()判定解码成功/失败
   - 失败时：仅对源端数据(hop_tx==hop_source)发送NACK_cpkt
   - NACK上限条件化: cpkt≥3时3次, 否则1次

2.3 Helper竞争 contend()
   得分公式:
     d_bneck = max(dist_to_source, dist_to_dest)   ← 瓶颈距离
     score = 0.40×min(c_pkt,1.5) + 0.25×(energy/INIT)
             + 0.35/(1 + prop_bneck/0.4s)

   退避分层fallback:
     - score > 0.90 → t = 0 (零退避)
     - cpkt < 3 && is_low_snr_selected → t = 0.02s (瓶颈最优首发)
     - 其余 → t = (1-score)×T_MAX_WINDOW×2 + 0.05s

   竞争取消: 其他helper收听到获胜者对该链路数据包
            → 触发cancel_event → 退让

   获胜helper发送自适应RV:
     cpkt≥2 → RV1 (30块, 2.0s)
     cpkt=1 → RV2 (60块, 4.0s)
     cpkt=0 → RV3 (90块, 6.0s)
     (源端始终发RV0, 仅helper侧自适应)

2.4 Grace ACK触发
   源端收到ACK时检查helper_ack_events[pid] → 触发Grace成功

2.5 低SNR预选
   run_sim中用瓶颈距离max(d_src, d_dst)预选最优helper,
   用于cpkt<3时的首发优先权(is_low_snr_selected)

4.4 关键发现
 (a) CA-CHARQ 延迟在0-3.0dB全域领先C-HARQ 5-11%
 (b) 能效在2.5dB+超越S&W基准（得益于helper自适应低功率）
 (c) 开销在1.0dB+低于C-HARQ和C-ARQ
 (d) 0dB处开销前三协作协议聚类——低SNR下协作传输不可避免
 (e) 差异化helper功率使EE在2.5dB反超S&W，验证文献阈值距离理论

4.5 CA-CHARQ 领先的五大机制
  1. MIESM置信度量化: Cpkt反馈使冗余按需分配
  2. Grace Period: 高置信时源端跳过重传(省100块/跳)
  3. 瓶颈距离竞争: 选出双向信道均衡的最优helper
  4. 自适应RV: 高置信发30块(2.0s)代替C-HARQ固定90块(6.0s)
  5. 差异化功率: helper按距离缩放Tx功率，改善能效

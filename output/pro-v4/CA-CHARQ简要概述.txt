CA-CHARQ v4 简要概述
—— 水下声学多跳网络中基于置信度量化的自适应协作HARQ协议
日期: 2026-06-27    版本: v4
================================================================================

一、协议目标
──────────────────────────────────────────────────────────────
CA-CHARQ（Confidence-Adaptive Cooperative HARQ）是面向水下声学多跳网络
的自适应协作HARQ协议。核心目标：

  (1) 端到端延迟全域领先：在所有信噪比条件下延迟低于所有对照协议
  (2) 开销全域领先协作协议：传输开销始终低于C-HARQ、C-ARQ等协作机制
  (3) 可靠性增强：在S&W ARQ和C-ARQ丢包的低SNR区，CA-CHARQ仍能恢复

二、工作流程（每跳三阶段）
──────────────────────────────────────────────────────────────

Phase 1 —— 源端发送 & Helper偷听
  源端发送RV0（63个RS编码符号，含57个系统符号+6个基础校验）。
  目的端将信号软置信度（SNR）累加至soft_buffer。
  交叠区域内3个helper偷听RV0，各自独立尝试RS解码。
  解码成功的helper存储副本等待协作用。

Phase 2 —— 置信度量化反馈
  目的端从累积soft_buffer计算 RS代数裕度 η：
      η = N_sym × avg_RS_SER / t_base
  即"期望RS符号错误数"与"基础纠错能力t=3"的比值。
  η映射为2-bit Cpkt值：
      η < 0.5  → Cpkt = 3   几乎能解码
      η < 1.5  → Cpkt = 2   中等置信
      η < 3.0  → Cpkt = 1   低置信
      η ≥ 3.0  → Cpkt = 0   极低置信
  Cpkt搭载在NACK包中，由目的端广播至源端和所有helper。

Phase 3a —— Grace Period（Cpkt=3时）
  源端暂缓立即重传，启动Grace定时器等待helper发起的ACK。
  所有已解码helper进入竞争阶段（加权退避定时器）。
  若某helper的校验块使目的端成功解码→目的端发送ACK→源端
  在Grace期内收到ACK→标记该跳成功→省去一次源端重传(63符号)。

Phase 3b —— 立即重传 + 协作（Cpkt<3时）
  源端立即重传RV0。helper按矩阵选中冗余版本(RV)发送校验块。
  目的端对源端重传做Chase合并，对helper校验块做IR增量合并。
  解码成功后发送ACK，源端进入下一跳。

三、冗余度(RV)选择机制（核心创新）
──────────────────────────────────────────────────────────────

决策依据二维信息：

  (A) Cpkt（目的端→源端链路质量）
      由目的端解码裕度 η 决定，反映了目的端"还差多少才能解码"。

  (B) Link Level（helper→目的端链路质量）
      由LinkQualityEstimator评估，融合两个信息源：
        - RSSI：helper窃听目的端NACK/ACK时测量的接收信号强度（EWMA平滑）
        - 历史成功率：helper发校验后目的端最终ACK的比例
      贝叶斯融合：Q = (N_obs × Q_hist + 5 × Q_rssi) / (N_obs + 5)
      离散化：Q > 0.85 → Good | 0.5 < Q < 0.85 → Medium | Q < 0.5 → Poor

两个维度交汇为4×3决策矩阵：

               Good          Medium        Poor
  Cpkt=3:    RV1.5 (9)     RV1.5 (9)     RV2  (12)
  Cpkt=2:    RV2   (12)    RV2   (12)    RV2.5(15)
  Cpkt=1:    RV3   (18)    RV3   (18)    RV3  (18)
  Cpkt=0:    RV3   (18)    RV3   (18)    RV3  (18)

设计逻辑：Cpkt决定基础冗余需求（置信高→少校验，置信低→多校验），
Link Level在此基础上微调（helper链路好时可进一步减冗余，差时加冗余）。

5级RV定义：
  RV1   =  6个RS校验符号（传输时间 0.03s）
  RV1.5 =  9个RS校验符号（传输时间 0.045s）
  RV2   = 12个RS校验符号（传输时间 0.06s）
  RV2.5 = 15个RS校验符号（传输时间 0.075s）
  RV3   = 18个RS校验符号（传输时间 0.09s）

四、底层物理模型
──────────────────────────────────────────────────────────────
  • RS编码：RS(63,57,t=3)母码，速率兼容扩展到N=81,t=12
  • 调制/衰落：QPSK + Rayleigh(K=0)块衰落，每QPSK符号独立
  • 信道：Thorp吸收 α≈4.1dB/km@20kHz + 柱面扩展(指数1.5)
  • Chase合并：源端重传RV0时SNR直接累加→等效SNR~Gamma(k,γ̄)分布
  • IR合并：helper校验块追加到soft_buffer尾部(位置189+)
  • 解码判决：per_rs_gaussian(逐符号RS SER→高斯逼近Poisson-Binomial→PER)

五、Helper竞争机制
──────────────────────────────────────────────────────────────
  • 3个helper通过加权退避定时器竞争
  • 得分公式：S = 0.4×min(c_pkt,1.5) + 0.25×(E_res/E_init) + 0.35/(1+t_prop/0.4)
    其中c_pkt为helper自身解码置信度，E_res为剩余能量，t_prop为瓶颈传播时延
  • S>0.90的helper零等待优先发送
  • 其余helper的退避定时器 t = (1-S)×T_WIN×2 + 0.05s
  • 先到期者开始发送所选RV，其他helper听到发送后触发取消事件退出竞争

六、系统参数
──────────────────────────────────────────────────────────────
  载波频率: 20kHz         跳距: 600m        跳数: 5
  源端功率: 15W           Helper功率: 按(d/600)^1.5缩放
  数据率: 1200bps         Helper数/跳: 3（竞争选择最优）
  RS码: (63,57,t=3)      调制: QPSK(2bit/sym)  衰落: Rayleigh K=0
  最大重传/跳: 8         发包间隔: ~30s(指数)  SIM_TIME: 8000s

七、对照协议
──────────────────────────────────────────────────────────────
  S&W ARQ: 无FEC，源端Chase合并重传RV0
  C-ARQ:   无FEC，1个预选helper发送RV0（空间分集+Chase）
  C-HARQ:  RS FEC固定，helper发送Pac-1+Pac-2（固定12个RS校验符号）
  CA-CHARQ: RS FEC自适应，Cpkt矩阵驱动的5级RV + Grace Period

八、关键结果（0-8dB，SimPy 8000s×3MC）
──────────────────────────────────────────────────────────────
  • 延迟：CA-CHARQ在0-8dB全域延迟最低
    0dB: CA(29s) < CH(81s) < S&W(fail) ≈ C-ARQ(fail)
    4dB: CA(16s) < CH(34s) < S&W(48s) ≈ C-ARQ(47s)
  • 开销：CA-CHARQ开销全域低于C-HARQ等协作协议
  • 可靠性：CA-CHARQ和C-HARQ在S&W/C-ARQ完全失败的低SNR区（0-1dB）
    仍能恢复100+端到端成功包
